# 事件可用性探查（静态审阅）

## 范围与判定口径

只读审阅项目 `AGENTS.md`、`README.md`、`apps/hana-desktop-pet/state-core.mjs`、`apps/hana-desktop-pet/index.js`，以及题目指定的宿主 1.1.7-beta `bundle/index.js`。未启动 GUI、未安装/审批 App、未触碰真实会话，也未做运行时探针。

`state-core.mjs` 顶部的 `EVENT_TYPES` 目前只有 13 项；`index.js` 在 `sdk.bus.subscribe(..., { types: EVENT_TYPES })` 订阅这些类型。宿主 v2 bus 包装层把订阅委托给 `hanaBus.subscribe`；除 `llm_usage` 的额外权限门控外，接收侧没有事件名白名单。宿主事件类型集合不是接收白名单：它用于标识宿主事件/阻止 App 冒用宿主事件名发射。

同源证据：宿主 `bundle/index.js:258810、258838` 的 `Iie`（注释标识 `event-bus`，对应 `hub/event-bus.ts`）实现 `subscribe` 和 `emit`；`emit` 把事件对象及第二参数交给回调，第二参数是 `sessionPath`。v2 App 上下文在 `143497、143533` 从 `hanaBus` 服务取 bus，并将订阅委托给 `g.subscribe(re, options)`；此接收包装只对 `llm_usage` 加权限检查。`270025` 注册的 `hanaBus` 服务创建 `Iie`，`276433、276501` 将该服务作为 `eventBus` 传入启动组合，Engine/Hub 接收该共享 bus（`259537、248451–248452`）。因此下文“确认可用”指**代码中存在触发后会送到该 App 总线的路径**，不代表本次运行时已观察到事件，更不代表官方稳定契约。

证据行号均指题目指定的宿主 `bundle/index.js`；项目文件证据给出可搜索片段。字段列表只列结构字段名，不记录任何取值。

## 确认可用

### `compaction_start` / `compaction_end`

- **结论：** 确认有 App 总线派发路径，但并非每一种压缩路径都必然发事件。
- **证据：** `bundle/index.js:18862` 的 `Ww` 将事件送入会话 Agent 事件流；`19028–19134` 有实际 `compaction_start` / `compaction_end` 构造；`34087` 的会话事件订阅器将收到的事件交给 Engine 的 `emitEvent`，并传入当前会话的 `sessionPath`。宿主 App 事件类型集合也包含两者（`142682`）。
- **session 归属：** 会话事件流的第二参数是该会话路径；不是全局 `null`。
- **payload 字段：** `compaction_start`: `type, reason, mode?`；`compaction_end`: `type, reason, mode?, result, aborted, willRetry, errorMessage?`。会话转发层在原事件没有 `agentId` 时补上 `agentId`。
- **频率 / 风险：** 被启用生命周期通知的每次压缩尝试至多形成一组开始/结束事件；失败路径也会发结束事件。`result` 可能包含压缩结果/摘要，`errorMessage` 可能含文本。**只能取事件类型，绝不能读 `result`、`errorMessage`；也不要保存 `sessionPath`。**

### `session_confirmation`

- **结论：** 确认有 App 总线派发路径。
- **证据：** `bundle/index.js:122126` 的用户交互确认流程直接 `emit` 该类型并传入请求所属的 `sessionPath`；`193034`、`195718` 另有宿主确认流程以 `emitEvent` 和会话路径派发。宿主 App 事件集合列出该类型（`142749`）。
- **session 归属：** 已审阅的会话确认调用传递请求所属的 `sessionPath`；不应假设所有未来调用方都一定提供路径。
- **payload 字段：** 顶层 `type, request`。常见 `request` 字段：`type, confirmId, kind, surface, status, title, body, subject, severity, actions, payload`；嵌套字段包括 `subject.label, subject.detail, actions.confirmLabel, actions.rejectLabel`。不同确认种类的 `payload` 还可能有 `message, requestedSchema, toolName, params` 等字段。
- **频率 / 风险：** 每次产生一个新的确认请求时发一次，不是按键流。`body/title/subject.detail/payload` 可能含用户文本、工具参数或审批细节。**只能取事件类型，绝不能读这些字段或其中的参数；也不要保存路径。**

### `confirmation_resolved`

- **结论：** 确认有 App 总线派发路径；不同来源的 session 归属不统一。
- **证据：** `bundle/index.js:226221` 的 Engine 确认存储回调通过 `_emitEvent` 派发并传入确认记录的 `sessionPath`；`120170` 的 App 输入面板路由通过 `emitEvent` 派发并传路径或 `null`；`130480` 的终端提案处理明确以 `null` 发射。宿主 App 事件类型集合包含该类型（`142702`）。
- **session 归属：** 常规会话确认通常带会话路径；终端提案来源明确为 `null`，另有调用可在缺路径时传 `null`。事件里的 `sessionId` 也可能为空。
- **payload 字段：** 可见来源的并集为 `type, confirmId, action, sessionId, value`（部分来源不提供 `sessionId` 或 `value`）。
- **频率 / 风险：** 每次确认实际解决时一次。`value` 是用户输入/决策结果，可能承载敏感内容；`sessionId` 是会话标识。**只能取事件类型，绝不能读 `value` 或 `sessionId`；不保存第二参数路径。**

### `interjection_dropped`

- **结论：** 确认有 App 总线派发路径。
- **证据：** `bundle/index.js:37595` 的会话强制释放路径在确实丢弃待处理插话时调用 `emitEvent`；宿主事件类型集合包含该事件（`142734`）。
- **session 归属：** 发射时传入被释放会话的路径。
- **payload 字段：** `type, reason, interjections`；数组项字段 `clientMessageId, displayText`。
- **频率 / 风险：** 一次释放/中止可能丢弃一批消息，按批发一条，不是每个普通回合都发。`displayText` 是待处理消息文本。**只能取事件类型，绝不能读 `displayText`；也不要保留 ID 或路径。**

### `voice_transcription_update`

- **结论：** 确认有 App 总线派发路径。
- **证据：** `bundle/index.js:223715` 的 `_emitTranscriptionUpdate` 调用 Engine `_emitEvent`，明确生成该类型；发射点传入从会话引用解析出的路径。宿主事件类型集合包含该事件（`142763`）。
- **session 归属：** 有 `sessionPath` 时第二参数为该路径；接口也允许只给 `sessionId`，此时路径可能为空。事件对象自身含 `sessionPath` 字段。
- **payload 字段：** `type, sessionId?, sessionPath, fileId, transcription`。
- **频率 / 风险：** 每次转写任务至少会在状态变化时通知；可见调用包含 pending 及 ready/failed 结果更新。`transcription` 可能含转写文本，`fileId` 与会话标识也属于敏感元数据。**只能取事件类型，绝不能读 `transcription`；不要记录 `fileId`、标识或路径。**

### `wait_started` / `wait_finished`

- **结论：** 确认有 App 总线派发路径。
- **证据：** `bundle/index.js:197913` 的等待登记存储在创建时发 `wait_started`，同一路径会在已全部终态时发 `wait_finished`；`198006` 的原子结算路径发 `wait_finished`。`226491` 将登记存储的 `emitEvent` 接到 Engine `_emitEvent`；App 总线同源链路见上文。`wait_started/wait_finished` 列在宿主 App 事件类型集合（`142765`）。
- **session 归属：** 等待登记创建会拒绝缺少 `sessionPath` 的请求；开始事件使用登记路径，结束事件使用该登记的路径，均为会话归属事件。
- **payload 字段：** 顶层 `type, registration`；`registration` 字段为 `waitId, sessionId, sessionPath, agentId, agentName, reason, taskIds, taskStates, status, createdAt, settledAt, memberAttempts, resultSummary?, match?, notification?`。
- **频率 / 风险：** 每个等待组创建一次 `wait_started`，结算一次 `wait_finished`；创建时已全部终态可能连续收到两者。嵌套 `sessionPath`、各类 ID、`reason`、`resultSummary`、`match`、`notification` 都不适合桌宠读取；后几项可能包含任务摘要或通知内容。**只能取事件类型，绝不能读这些字段的值。**

### `workflow_progress`

- **结论：** 确认有 App 总线派发路径。
- **证据：** `bundle/index.js:201803、201838、201858、202042` 的 workflow 工具将恢复提示或进度回调构造成 `workflow_progress` 并通过 `emitEvent` 派发；异步工作流传父会话路径，兼容的同步工作流也传父路径参数。宿主事件类型集合包含该类型（`142712`）。
- **session 归属：** 第二参数是父会话路径参数；若调用方没有路径，不能排除 `null`。不是子会话路径。
- **payload 字段：** 可见形状为 `type, taskId?` 加进度字段；回调来源可带 `message` 或 `title`，恢复提示带 `taskId, message`。不排除未来或其他调用方增加字段。
- **频率 / 风险：** 工作流脚本每次调用日志/阶段进度、节点重试等都可能发，单个 workflow 可多次发。`message/title` 是自由文本，可能包含用户写的流程内容或错误文本。**只能取事件类型，绝不能读 `message/title` 或其他进度字段。**

## 有证据但不确定

### `queue_update`

- **结论：** 有被宿主识别和转发的条件，但静态证据不能证明当前宿主确实产生它。
- **证据：** `bundle/index.js:142682` 将 `queue_update` 列入宿主核心事件类型；`34087` 的会话事件订阅器会把该会话流中收到的事件整体转发到 Engine/App 总线。全文只找到类型声明及通用转发，**没有找到 `queue_update` 的实际发射点**。
- **session 归属：** 若来自该会话事件流，转发时第二参数是该会话路径；但未找到生产者，不能据此确认运行时每次都有关联路径。
- **payload 字段：** 未找到构造点，字段形状未知；通用转发不对 payload 做事件专属的字段白名单。不能安全假设队列内容不含正文。
- **频率 / 风险：** 未知。若真实生产者按队列变动发射，可能高频；在探针验证前不接入状态映射，也不要读取 payload。

## 找不到证据

无完全没有宿主事件类型/转发线索的目标事件。`queue_update` 虽无发射点，但有类型声明和条件转发证据，因此归入“有证据但不确定”，而不是判为不可用。

## 明确不可用

无。没有发现这些类型被宿主明确禁止 App 订阅；未找到发射点也不能推导为明确不可用。

## 最小运行时探针（需罐头批准后才能执行）

静态分析无法证实 `queue_update` 的实际生产情况，也没有实际运行证据证明当前安装包会把上述事件送达 App。可在获准后制作一个临时 v2 探针 App：仅调用 `sdk.bus.subscribe` 订阅本报告列出的类型（不订阅 `llm_usage`），不声明会话读取、网络、文件或其他权限，不提供路由/工具，不持久化数据。回调只在内存中计数，并记录：`event.type`、`sessionPath !== null/undefined` 的布尔值、事件字段名树（只枚举键名，限制深度/数组项数）；**绝不读取、打印、序列化或保存任何字段值**，尤其不触碰 `body`、`displayText`、`transcription`、`result`、`params`、`value`、路径或 ID。

探针验证应在罐头批准临时 App 安装/审批后，由罐头控制触发条件；批准前不创建、不安装、不审批，也不操作真实会话。即使探针收到事件，也只证明该宿主构建中的运行时路径，不构成官方稳定性承诺。

## 结论与置信度

- **静态派发路径高置信度：** `compaction_start/end`、`session_confirmation`、`confirmation_resolved`、`interjection_dropped`、`voice_transcription_update`、`wait_started/finished`、`workflow_progress`。
- **静态证据中等、运行时未确认：** `queue_update`。它在事件类型列表中且有通用转发器，但没有找到发射调用点。
- **尚未验证：** 任何事件的实际运行时送达率、空路径边界及官方稳定性；没有创建或运行探针。
